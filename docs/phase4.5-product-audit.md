# Phase 4.5 小程序产品走查与内容审计

> 审计日期：2026-07-18
> 审计范围：班主任、年级主任的新 MVP 页面
> 审计性质：只读产品审计，不修改产品代码，不进入 Phase 5
> 主要尺寸：390px；补充尺寸：360px、430px

## 0. 结论摘要

Phase 1—4 已经形成可运行的班主任任务、观察反馈、主动上报和复测提醒闭环。权限拦截、Repository 写入、列表与首页数量同步等工程基础总体有效。本轮未发现学生敏感信息跨角色泄露等 P0 问题。

但当前页面仍明显带有“开发验收稿”特征，而不是收敛后的真实小程序：

- 存在 3 项 P1：表单可绕过离开确认、取消任务仍显示有效截止时间、年级督办数据存在重复与关联不一致。
- 多处直接展示 `Repository`、`Demo Clock`、`Phase 5`、迁移说明等开发术语。
- 任务详情、复测详情、上报成功页反复展示同一状态和权限边界。
- 班主任首页第一屏被统计、说明和复测提醒占据，最近待办位于较深位置。
- 年级主任的完整督办尚未实现，这是 Phase 5 的计划缺口，不按 P0/P1 Bug 处理；但当前占位页把开发阶段信息直接呈现给终端用户，属于内容问题。

建议下一轮先修数据与流程矛盾，再删减说明和重复状态，最后做视觉细节调整。不要以增加新页面的方式解决本轮问题。

## 3. 流程走查结果

### 3.1 班主任链路 A：普通观察反馈

```text
首页 → 待处理任务列表 → 普通任务详情 → 填写观察 → 确认提交
→ 详情出现新记录 → 返回列表 → 返回首页
```

结果：主链路通过。Repository 保存了真实输入，详情新增记录，待反馈筛选移除已提交任务，首页待处理数同步减少。

体验问题：

- 首页最近待办位于统计、提醒与说明之后，首屏主任务不够直接。
- 详情页在多个区域重复展示状态、截止和当前动作。
- 表单可通过底部导航直接离开，绕过表单自己的离开确认。

### 3.2 班主任链路 B：退回补充

```text
被退回任务 → 查看退回原因和原反馈 → 补充反馈
→ 提交 → 详情保留原记录并新增补充记录
```

结果：数据历史和关联关系通过。原反馈没有被覆盖，补充记录单独追加。

体验问题：

- 退回状态、超时状态、当前动作、退回原因在第一屏重复出现。
- 详情和补充表单都展示较多相同背景信息，页面过长。

### 3.3 班主任链路 C：主动异常上报

```text
首页或底部“上报” → 填写事实线索 → 确认提交
→ 成功状态 → 我的上报 → 上报详情
```

结果：流程连通；上报不会生成协作任务，也不会改变首页待处理数。

体验问题：

- 表单直接显示 `Repository` 等实现术语。
- 事实表达边界在入口说明、字段说明、提示卡和确认弹层中重复。
- 成功页与详情都多次重复“已提交待复核”。
- 自动保存草稿与显式“保存草稿”并存，用户难以判断是否还需要手动保存。

### 3.4 班主任链路 D：复测提醒

```text
首页或任务列表 → 复测提醒详情 → 选择提醒方式
→ 确认已提醒 → 返回首页和任务列表
```

结果：状态同步通过；`submitted` 正确表达“已提醒”，页面没有让班主任填写复测结果或点击完成复测。

体验问题：

- “只负责提醒、不负责录入结果”在说明、提示条和只读按钮附近重复。
- 当前状态在 Badge、信息行、结果提示和底部按钮重复表达。

### 3.5 班主任链路 E：草稿、失败、取消、无权限

结果：

- 刷新后草稿可恢复。
- 写入失败时正文保留，不生成假记录，可重试。
- 无权限 URL 被统一拦截。
- 已完成和已取消任务不能进入可提交表单。

问题：

- 表单中的返回按钮会询问保存或舍弃，但底部导航可直接离开；两种离开方式行为不一致。
- 整页读取失败没有稳定可触达的用户态，当前只能验证写入失败。

### 3.6 年级主任链路

```text
角色选择 → 首页 → 督办入口 → 我的
→ 尝试访问班主任页面 → 切换角色
```

结果：

- 年级主任不能进入班主任任务页面。
- 切换角色后，浏览器返回不会重新显示上一角色敏感页面。
- 首页有本年级聚合进度与最近事项。

计划缺口：

- 督办列表和详情尚未进入 Phase 5。当前所有督办入口进入占位页。
- 该缺口不作为 P0/P1 Bug，也不建议在本轮提前开发。

内容问题：

- 占位页直接展示 “Phase 5”“后续阶段迁移”“筛选意图”等开发语言。

## 4. 可见内容分级

分级定义：

- **A 当前必须看到**：完成当前任务不可缺少。
- **B 需要时再查看**：应渐进披露或放入次级区域。
- **C 只在异常时展示**：正常状态不应常驻。
- **D 不应向终端用户展示**：开发、验收、架构或内部迁移信息。

## 8. 重复内容清单

重复等级：

- **R1**：完全重复，删除。
- **R2**：语义重复，合并。
- **R3**：不同层级各有价值，保留。
- **R4**：安全或结果确认需要重复，说明原因。

| 页面 | 重复内容 | 等级 | 建议 |
|---|---|---|---|
| 任务详情 | Badge、任务状态、当前行动、底部按钮表达同一状态 | R1/R2 | 合并为单一状态摘要 |
| 退回详情 | “需补充”与“已超时”在多块区域重复 | R2 | 状态摘要保留一次，退回原因单独保留 |
| 观察反馈 | 学生姓名/班级在标题、摘要卡、字段区相邻重复 | R2 | 合并为一行紧凑学生信息 |
| 观察反馈 | “只写事实、不做诊断”多次出现 | R2 | 保留一个字段提示，示例折叠 |
| 异常上报 | 事实线索边界在入口、字段、说明卡、确认弹层重复 | R2 | 正常页保留一次，确认只保留摘要 |
| 异常上报 | 安全风险强提示在表单和提交确认中重复 | R4 | 必须保留；分别用于操作前和最终确认 |
| 上报成功 | 标题、Badge、状态行均为“已提交待复核” | R1 | 保留标题或状态之一 |
| 我的上报详情 | 页头状态、状态行、边界卡重复 | R1/R2 | 页头一次状态即可 |
| 复测详情 | 待提醒/已提醒状态在 3–4 处重复 | R1/R2 | 保留主状态 + 操作记录 |
| 复测详情 | 不录入复测结果的边界反复出现 | R2 | 保留一次轻提示 |
| 首页 | 超时数量和超时提醒条 | R3 | 数字用于概览，提醒条用于行动，可以保留但需压缩 |
| 首页 | 上报快捷入口和底部上报导航 | R3 | 一个情景入口、一个全局入口，保留 |
| 补充反馈 | 退回原因在详情与表单再次出现 | R3 | 用户填写时需要上下文，保留但压缩 |
| 补充反馈 | 原反馈在详情与补充表单再次出现 | R3 | 防止脱离上下文，保留可折叠摘要 |
| 我的 | 顶部角色身份与“当前身份”卡重复 | R2 | 合并 |
| 每页 | 隐私与角色边界常驻卡 | R2 | 移到首次说明或帮助，异常时再提示 |

## 11. 产品待决策项

仅有以下事项无法完全依据当前规格和代码直接决定：

1. **Demo 班主任是单班班主任还是多班协作教师？**
   当前权限数据允许多个班级，但首页只展示第一个班级。确认后应统一身份文案和可见学生范围；Repository 仍需保持服务端式校验。

2. **Phase 5 完成前，年级主任督办入口如何展示？**
   可选方向是暂时隐藏、禁用并给自然说明，或保留作品集占位。无论选择哪种，都不应展示 Phase 编号和迁移术语。

3. **“演示模式”是否仅保留在角色选择页？**
   作品集演示可能需要提示当前数据为模拟，但持续出现在产品页会削弱沉浸感。建议默认只在角色选择页出现。

## 12. 计划缺口

以下内容不是本轮 Bug，也不应提前进入开发：

- 年级主任完整督办列表和详情：Phase 5。
- 年级主任督办操作与留痕：Phase 5。
- 全量离线与整页读取失败体验：后续异常态与精修阶段。
- 心理老师和校长新 MVP 页面：不在本轮审计范围，当前仍为 legacy。

## 13. 最终判断

当前产品已经具备可证明业务闭环的工程基础，但还没有完成“从规格验收稿到真实终端界面”的内容收敛。主要问题不是缺功能，而是：

1. 状态和边界被重复解释；
2. 开发术语泄漏到 UI；
3. 第一屏任务优先级不够清晰；
4. 少量派生状态和数据关联存在真实矛盾；
5. 尚未实现的阶段被错误包装为正式入口。

下一轮应按 **P1 数据与流程矛盾 → 开发术语清理 → 页面状态去重 → 首页与表单层级收敛 → P3 视觉统一** 的顺序修正。Phase 5 的年级督办功能应继续按既定阶段独立开发，不应被本轮审计问题带动提前扩展。
