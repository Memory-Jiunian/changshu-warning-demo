# 班主任核心链路 UX/UI V2 基线

## 1. 当前四页的 UX 问题

### 班主任首页

- 顶部身份区仍以完整卡片表达，占用首屏高度。
- 三张完整任务卡与任务列表密度接近，首页缺少“摘要视图”的明确差异。
- 最高优先任务、其他待办、统计和复测提醒之间的层级仍偏平均。
- 第一屏只能完整看到一至两项任务，核心行动出现得不够快。

### 任务列表

- “全部 / 待反馈 / 待补充 / 已超时 / 复测提醒 / 已提交 / 已完成”同时平铺，用户需要理解过多细状态。
- 当前任务和历史记录混在同一个默认列表中，行动项与归档项没有一级区分。
- 任务卡中的状态、任务类型和截止信息均使用胶囊样式，视觉语义接近。

### 待反馈任务详情

- 状态摘要和任务说明仍是两个同权重白色卡片。
- 学生、任务目的和观察重点没有形成清晰的阅读顺序。
- 无反馈时仍显示“我的反馈记录”空区域，增加无效页面长度。
- 二级详情仍显示全局底部导航，与固定操作栏形成两个导航层级。

### 填写观察反馈

- 表单主体仍使用带阴影的大卡片，和内容详情页的视觉表达相同。
- 所有字段在同一连续容器中，主字段与次级字段权重不够明确。
- 全局底部导航与固定提交操作区同时存在。
- 页面背景仍继承全局渐变，削弱了长表单的稳定阅读感。

## 2. 页面层级定义

### 一级页面

承担跨模块导航和当前角色的任务总览：

- `#/mvp/home`
- `#/mvp/teacher/tasks`
- `#/mvp/profile`

### 二级页面

围绕一个对象完成查看与决策：

- `#/mvp/teacher/tasks/:taskId`

### 三级页面

执行单一、可提交的任务动作：

- `#/mvp/teacher/tasks/:taskId/feedback`

## 3. 底部导航显示规则

仅一级页面显示全局底部导航：

- 首页：显示；
- 任务列表：显示；
- 我的：显示；
- 任务详情：隐藏；
- 观察反馈：隐藏。

该规则由路由壳层决定是否渲染 `BottomNavigation`，不通过 CSS 遮挡实现。

## 4. 底部操作栏显示规则

- 任务详情仅在当前任务可执行时显示 `BottomActionBar`。
- 待反馈任务显示“填写观察反馈”。
- 待补充任务显示“补充反馈”。
- 已提交、已完成、已取消任务不显示底部操作栏。
- 反馈表单只显示一个固定操作区，包含返回和提交。
- 固定操作区位于设备底部，不与全局底部导航叠加。

## 5. 首页信息顺序

1. 紧凑身份栏：姓名、角色、班级；
2. 最高优先级任务：完整摘要与明确状态；
3. 另外最多两项紧凑待办；
4. 紧凑统计：待处理、已超时、今日提醒；
5. 今日复测提醒；
6. 主动上报快捷入口。

首页回答：“今天最先处理什么？”

## 6. 任务列表结构

任务列表先提供两个一级视图：

- **待处理**：待反馈、待补充、已超时、复测待提醒；
- **历史记录**：已提交、已完成、已提醒、已取消。

默认进入“待处理”。一级视图下继续提供由 Selector 驱动的细分筛选，不新增或修改任务状态。

- 待处理细分：全部待处理、待反馈、待补充、已超时、复测提醒；
- 历史细分：全部历史、已提交、已完成。

复测任务的“已提醒”和普通任务的“已提交”仍共用领域状态 `submitted`，仅由现有 Selector 和任务类型转换展示文案。

## 7. 任务卡信息优先级

从高到低：

1. 学生姓名；
2. 班级；
3. 一个主状态 Badge；
4. 任务类型文本；
5. 两行以内任务摘要；
6. 截止或历史时间。

约束：

- 整卡点击进入详情；
- 最多一个彩色 Badge；
- 任务类型和截止时间使用文字或图标信息行，不再同时使用多个胶囊；
- 不在同一卡中同时强调优先级、紧急度、类型、状态和截止。

## 8. 详情页信息层级

1. 返回与页面标题；
2. 单一状态摘要：状态、任务类型、截止时间；
3. 学生与任务目的；
4. 本次观察重点；
5. 历史反馈，仅当存在记录时显示；
6. 当前唯一主操作。

详情页使用一张主内容面和轻量分隔区，不使用三张以上同权重白色卡片。

## 9. 表单页信息层级

1. 返回、页面标题和轻量草稿状态；
2. 学生、班级、任务类型摘要；
3. 第一组：观察时间与场景；
4. 主字段：事实观察与折叠示例；
5. 次级字段：频率、持续时间、补充说明；
6. 安全风险选择与条件性强提示；
7. 固定底部操作区。

表单使用平铺字段组和分割线，不使用大阴影卡片。校验、草稿、确认和提交逻辑保持不变。

## 10. UI V2 Token

| Token | V2 规则 |
|---|---|
| 页面背景 | `#F4F5F7` 中性浅灰，不使用全页渐变 |
| 内容面 | `#FFFFFF` |
| 主色 | 延续紫色，仅用于主操作、选中态和少量状态 |
| 普通容器圆角 | `12px` |
| 任务卡圆角 | `16px` |
| 按钮圆角 | `12px` |
| 普通阴影 | 无阴影或 `0 1px 2px rgba(24, 30, 58, 0.04)` |
| 浮层阴影 | 仅用于确认弹层和固定操作区 |
| 页面边距 | `16px` |
| 区块间距 | `24px` |
| H1 | `22px / 700` |
| H2 | `18px / 700` |
| 正文 | `14–16px / 400–600` |
| 辅助信息 | `12–13px` |
| 主要触控区 | 不低于 `44px` |

## 11. 组件保留、修改和废弃

### 保留

- `BottomNavigation`
- `BottomActionBar`
- `DraftSaveStatus`
- `TaskStatusBadge`
- `ObservationRecordCard`
- `UiButton`
- `UiFormField`
- `UiInput`
- `UiTextarea`
- `UiRadioGroup`
- `ConfirmDialog`

### 修改

- `AppShell`：根据路由层级决定是否渲染底部导航；
- `RoleHeader`：支持紧凑身份栏；
- `HomeTaskCard`：拆分首页重点卡与紧凑待办行；
- `TeacherTaskCard`：改为 V2 单状态任务卡；
- 任务筛选：增加“待处理 / 历史记录”一级分段；
- `Card` 的使用方式：四个试点页改用无阴影内容面和分隔区。

### 本轮不再使用

- 首页三张完整任务卡的表达；
- 任务列表七个同层级筛选同时展示；
- 详情页空反馈历史占位；
- 表单大阴影卡片；
- 二级、三级页面的全局底部导航。

## 12. 对其他页面的后续迁移影响

本轮只建立可推广基线，不迁移以下页面：

- 异常上报；
- 我的上报与上报详情；
- 复测提醒详情；
- 年级主任首页、督办占位与“我的”；
- legacy 心理老师与校长页面。

后续迁移时应复用本轮导航层级、页面背景、容器、状态和固定操作区规则，但不得直接复制班主任任务的业务结构。Phase 5 仍只负责年级主任督办能力，Phase 6 再处理全产品视觉统一。
