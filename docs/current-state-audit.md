# 当前状态审计（Phase 0）

> 审计日期：2026-07-17
> 审计范围：当前仓库与“畅树小程序优化开发包 v1”
> 本阶段约束：只盘点，不修改业务代码、路由、Mock、样式或页面行为

## 1. 结论摘要

当前仓库是一个可构建、可静态部署的 React 移动端 Demo，已包含班主任、心理老师、年级主任、校级管理者四种演示视角，以及任务详情、观察反馈、线索上报、督办确认和校级概览等页面。

它与优化开发包的新定位存在结构性差距：

1. 当前 Demo 仍把心理老师的专业确认、复测、转介和闭环操作放在小程序中；新规格要求这些专业操作回到管理终端。
2. 当前 Demo 提供校级管理者移动总览；新 MVP 明确校长不进入小程序个案流程。
3. 当前 `WarningTask` 同时承载管理终端处置结果、小程序协作状态和页面展示文案，尚未分离领域真值。
4. `overdue` 当前是可写 `statusKey`，新规格要求它由 `dueAt` 和当前时间派生。
5. 观察反馈表单具有完整视觉结构，但提交时写入的是固定文本，不是用户实际填写值；草稿、校验、二次确认、失败重试和防重复提交尚未实现。
6. 当前数据由 `src/mockData.ts` 与 `App.tsx` 内部 React state 共同维护，没有统一 Provider / Repository，也没有刷新持久化。

因此，后续应先执行 Phase 1 的领域模型与统一真值，再做角色壳层和页面迁移。直接继续叠加页面或视觉会扩大数据与权限不一致。

## 7. 页面保留、重命名与移除建议

### 7.1 保留并迁移

- 班主任首页的待办概览与最近任务卡。
- 班主任任务详情中的有限学生信息、任务说明、观察重点和本人历史反馈。
- 填写观察反馈的移动表单框架与固定底部操作区。
- 班主任主动上报的事实描述方向。
- 年级主任的脱敏任务摘要、提醒确认弹层和督办留痕概念。
- 现有轻量 `UiButton`、`UiCard`、`UiBadge`、`UiFormField`、`UiSheet`。

### 7.2 重命名或重新定义

- “上报协作线索”改为“主动上报异常”，明确它进入待复核线索池，不自动形成预警。
- 班主任的“关注等级”统一改为“任务紧急程度”或“需优先关注”，不展示专业风险定级。
- 当前“逾期未更新”改为由截止时间派生的显示标签，而不是任务真值状态。
- 当前“已反馈待确认”映射为小程序任务 `submitted`，心理老师接受后映射为 `completed`。
- 当前“需补充”映射为任务 `returned`，补充提交必须新增记录。
- 年级主任“年级督办”只包含超时或明确指派事项，不是全年级任务总览。

### 7.3 从小程序 MVP 移除

- 心理老师在小程序执行“确认进入干预、安排复测、持续关注、转介建议、解除关注”。
- 心理老师在小程序新增专业记录。
- 校长的小程序个案或任务入口。
- 面向班主任、年级主任的完整专业处置时间线。
- 直接写入或展示管理终端七种主处置状态的操作。

这里的“移除”是新 IA 结论，不代表 Phase 0 删除代码。

## 8. 当前角色与权限盘点

| 角色 | 当前代码能力 | 新规格能力 | 差距 |
|---|---|---|---|
| 班主任 `homeroomTeacher` | 看本人 `owner` 匹配任务、填观察、上报线索 | 核心角色；仅事实上报、观察反馈、复测提醒确认 | 方向基本一致，但缺真实表单、历史新增、复测专页和异常态 |
| 年级主任 `gradeDirector` | 看本年级全部任务、查看脱敏详情、发提醒 | 只看超时或明确指派事项，新增督办记录 | 当前可见范围过宽，缺 `needSupervision` / `supervisorId` 真值 |
| 心理老师 `counselor` | 看完整任务、AI 摘要和时间线，并可修改处置结果 | 管理终端为主；小程序最多只读协作摘要 | 当前明显越过新规格边界 |
| 校级管理者 `principal` | 看移动聚合页并发起督办 | 本轮不进入小程序个案流程 | 当前属于旧作品集范围，不属于新 MVP |

### 8.1 当前权限过滤实现

- 班主任：按 `task.owner === role.teacherName` 过滤。
- 年级主任：按 `task.grade === role.grade` 过滤。
- 心理老师：查看全部任务。
- 校长：任务列表为空，但有独立校级聚合页。
- 时间线通过 `audience` 做基础过滤。

### 8.2 权限缺口

- 没有稳定的用户 ID、班级 ID、年级 ID、任务接收人 ID。
- 年级主任没有“超时或明确指派”过滤条件。
- 无权限 URL 只覆盖部分页面；校级路由存在绕过。
- 班主任任务卡仍可携带管理终端结果字段，只是页面选择性隐藏。
- 当前角色切换是前端状态，不模拟真实登录与权限；这符合 Demo，但必须明确“演示模式”。

## 10. 当前数据模型与事件缺口

### 10.1 当前 `WarningTask` 混合了三类信息

1. 管理终端专业字段：`attention`、`result`、AI 线索、最终结论。
2. 小程序协作字段：`owner`、`deadline`、`records`、`timeline`。
3. 页面展示字段：`status`、`nextAction`、`desensitizedFlow`、`resourcePressure`。

后果是页面操作可直接把 `statusKey` 从待反馈改为“跟进中 / 复测 / 转介 / 闭环”，等同于小程序修改管理终端主处置结果。

### 10.2 当前写操作

| 操作 | 当前结果 | 与新契约差距 |
|---|---|---|
| 提交观察反馈 | `App.tsx` 直接 `setWarningTasks`，新增一条固定文本记录 | 应通过 Repository；应写用户输入；需要 Result、防重复、失败和草稿 |
| 心理老师确认 | 小程序直接修改任务状态与处置结果 | 新规格要求在管理终端完成，小程序只读同步 |
| 请求补充 | 把原任务改回待反馈并追加时间线 | 新规格要求原反馈保留；补充任务/请求应独立建模或关联旧记录 |
| 年级主任提醒 | 追加同一任务时间线 | 应写独立 `SupervisionRecord`，不改变原任务责任 |
| 校长督办 | 写入页面局部 `principalLogs` | 不属于新小程序 MVP，且不是共享真值 |
| 主动上报 | 只显示 Toast | 应新增上报记录，并进入管理终端待复核线索池 Mock |

### 10.3 缺失的事件

- `task.read`
- `feedback.revision_submitted`
- `teacher.abnormal_reported` 的真实记录
- `retest.reminder_confirmed`
- `supervision.recorded` 的独立记录
- `task.cancelled`
- `warning.closed` 对活动任务的完成/取消处理
- `assignee.changed`

`UiSheet` 已用于补充请求、年级主任提醒和校级督办确认，具备取消和确认动作。通知方式与短信均为前端 Mock。新规格下只保留年级主任督办方向；心理老师补充请求应被建模为管理终端事件输入。
