# 03 核心业务流程

## 1. 流程 A：班主任主动上报异常

```text
班主任进入“上报”
→ 选择学生
→ 填写观察时间、场景与事实
→ 选择是否需要立即线下处理
→ 确认内容不包含主观诊断
→ 提交
→ 生成异常上报记录
→ 管理终端待复核线索池新增事项
```

### 成功结果

- 小程序展示提交成功和记录编号；
- 记录状态为“已提交”；
- 管理终端获得来源为“班主任上报”的线索；
- 不自动形成正式预警；
- 不自动显示风险等级。

### 禁止

- 班主任选择中风险、高风险或危险；
- 系统根据表单自动确认预警；
- 用“抑郁症、双相、人格障碍”等诊断标签作为必填选项；
- 允许删除已进入管理终端的历史上报。

---

## 2. 流程 B：正式预警后生成默认协作任务

```text
心理老师在管理终端确认正式预警
→ 系统生成班主任协作任务
→ 小程序首页待办数量增加
→ 班主任首次打开任务
→ 系统记录已读时间
→ 班主任查看任务要求
→ 提交事实观察
→ 管理终端收到反馈
```

默认协作任务与“额外请求补充反馈”是两条不同事件。

### 默认任务目的

帮助心理老师获得学生在日常校园环境中的事实观察，不让班主任承担专业判断。

---

## 3. 流程 C：心理老师额外请求补充反馈

```text
心理老师在管理终端点击“请求补充反馈”
→ 生成新的反馈任务
→ 任务关联原预警事项
→ 班主任收到新任务
→ 提交新反馈
→ 历史反馈保留
```

规则：

- 每次请求生成独立任务或独立请求记录；
- 新提交不能覆盖旧反馈；
- 任务说明明确本次需要补充的观察点；
- 超时由 `dueAt` 派生；
- 本 MVP 默认接收人只设为对应班主任。

---

## 4. 流程 D：反馈被退回补充

```text
班主任提交反馈
→ 心理老师在管理终端查看
→ 信息不足，退回并填写补充要求
→ 小程序任务显示“待补充”
→ 班主任提交补充记录
→ 原记录保留，新记录关联退回原因
```

“退回”不是删除，不能覆盖原内容。

---

## 5. 流程 E：复测提醒

```text
心理老师在管理终端安排复测
→ 系统生成班主任复测提醒
→ 复测前一天再次提醒
→ 班主任查看时间、地点和提醒要求
→ 班主任确认“已提醒学生”
→ 学生在学生端完成复测
→ 小程序提醒任务完成
→ 心理老师在管理终端查看结果并更新主状态
```

规则：

- 班主任只确认已提醒，不录入复测结果；
- 学生未完成复测时，不能由班主任点击“复测已完成”；
- 转介结果不会自动产生复测提醒；
- 只有管理终端“安排复测”才能生成提醒。

---

## 6. 流程 F：年级主任督办

```text
班主任任务超时或被心理老师明确请求协调
→ 系统生成督办事项
→ 年级主任查看任务摘要
→ 联系班主任或协调资源
→ 记录督办方式和结果
→ 班主任任务仍保持原完成责任
```

规则：

- 年级主任不能代填观察反馈；
- 督办记录不会改变管理终端主处置状态；
- 年级主任默认看不到反馈正文；
- 没有超时或明确指派时，不自动扩大年级主任可见范围。

---

## 7. 流程 G：任务取消与事项闭环

### 任务取消

发生以下事件时可取消未完成任务：

- 管理终端撤回反馈请求；
- 学生班级或责任人发生有效变更；
- 预警事项被合法关闭；
- 系统发现重复任务。

取消后：

- 任务只读；
- 展示取消原因和时间；
- 草稿不得继续提交；
- 历史已提交记录保留。

### 已闭环

管理终端完成闭环后：

- 小程序不允许继续提交该事项的新反馈；
- 已完成记录进入历史；
- 是否发送闭环通知采用最小通知原则：只有仍持有活动任务的协作人收到“事项已结束，无需继续操作”，不展示专业结论。
