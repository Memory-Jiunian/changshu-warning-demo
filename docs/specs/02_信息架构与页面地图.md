# 02 信息架构与页面地图

## 1. 导航原则

小程序底部导航以“高频任务”而不是“后台模块”组织。

### 班主任导航

1. `首页`
2. `任务`
3. `上报`
4. `我的`

### 年级主任导航

1. `首页`
2. `督办`
3. `消息`（P1）
4. `我的`

Demo 可在“我的”中提供角色切换，但角色切换只是演示工具，不代表真实产品允许用户任意切换权限。

## 3. 首页信息优先级

### 班主任首页

从上到下：

1. 身份与日期；
2. 必须处理的数量；
3. 超时提示；
4. 今日复测提醒；
5. 最近三条待办；
6. 主动上报快捷入口；
7. 最近提交结果。

首页不展示：

- 风险趋势图；
- 全校统计；
- 管理终端的七状态分布；
- 心理老师干预进度；
- 大段通知公告。

### 年级主任首页

1. 管理年级；
2. 待督办数量；
3. 超时数量；
4. 按班级聚合的协作进度；
5. 最近督办事项。

不展示学生风险等级分布和学生列表总览。

---

## 4. 任务列表分组

任务列表按“用户需要采取的行动”分组，不按管理终端主状态分组。

推荐筛选：

- 全部；
- 待反馈；
- 待补充；
- 复测提醒；
- 已提交；
- 已完成。

排序：

```text
已超时
→ 今天到期
→ 任务紧急程度
→ 截止时间
→ 创建时间
```

风险等级只用于系统派生优先级，不直接向班主任显示。

---

## 5. 页面跳转与返回

### 首页 → 任务详情

返回首页时：

- 保留滚动位置；
- 数量根据最新数据重新计算；
- 已完成任务从待处理列表移除；
- 若提交失败，任务仍保留。

### 任务详情 → 填写反馈

返回详情时：

- 成功：展示新增记录并更新状态；
- 草稿：恢复未提交内容；
- 取消：不改变任务状态。

### 年级主任督办 → 返回列表

- 保留筛选；
- 新督办记录立即出现；
- 督办不会代替班主任完成任务。
