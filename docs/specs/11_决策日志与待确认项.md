# 11 决策日志与待确认项

## 1. 已冻结决策

| 决策 | 结论 |
|---|---|
| 小程序定位 | 一线事实入口 + 正式预警后的移动协作层 |
| 专业判断位置 | 管理终端 |
| 核心角色 | 班主任、年级主任 |
| 校长个案入口 | 不进入小程序 MVP |
| 默认任务 | 确认正式预警后自动生成班主任协作任务 |
| 额外反馈 | 与默认任务分开建模 |
| 反馈记录 | 新增，不覆盖 |
| 超时 | 由截止时间派生 |
| 复测提醒 | 只有管理终端安排复测后生成 |
| 转介与复测 | 转介结果不自动生成复测 |
| 风险等级 | 班主任不展示专业定级，展示任务紧急程度 |
| 技术栈 | React + TypeScript + Vite + 纯 CSS |
| UI 基础 | 复用现有 shadcn-inspired 轻量组件，不引入完整依赖 |

---

## 2. 本包为了可执行而采用的默认决策

1. 额外反馈请求只发给对应班主任；
2. 年级主任只处理超时或明确指派事项；
3. 系统生成默认协作任务作为独立事件；
4. 闭环时仅通知仍有活动任务的协作人；
5. 心理老师不在小程序完成专业处置；
6. 任务取消后历史记录保留；
7. 班主任异常上报不支持附件上传；
8. 年级主任默认看不到反馈正文。

---

## 3. 后续可能影响上下游的问题

### 3.1 管理终端通知规则变更

若最终确定转介、复测状态更新或闭环后需要通知更多角色，需要同步修改：

- 事件契约；
- 任务类型；
- 首页数量；
- 消息中心；
- Mock；
- 验收矩阵；
- 作品集流程图。

### 3.2 年级主任可否接收普通反馈请求

若允许，需要新增：

- 反馈任务接收人选择；
- 年级主任事实反馈表单；
- 权限范围；
- 管理终端反馈来源展示；
- 班主任与年级主任反馈区分。

这会显著扩大角色边界，不能只改一个下拉框。

### 3.3 班主任是否显示风险等级

本包默认不显示。若未来决定显示，需要同时说明：

- 展示目的；
- 风险等级解释；
- 防止班主任进行专业判断的文案；
- 任务紧急程度与风险等级的关系；
- 隐私和误读风险。

### 3.4 校长是否需要移动总览

如未来加入，应做脱敏聚合页，而不是复用年级主任或班主任页面。需要单独定义统计口径、小数量保护与下钻限制。

---

## 4. 变更检查表

任何流程修改都必须检查：

- 上游由谁触发；
- 小程序是否生成/取消任务；
- 哪个角色可见；
- 是否新增通知；
- 提交后管理终端显示什么；
- 主状态是否被误改；
- 历史记录是否保留；
- 首页数量是否变化；
- 列表筛选是否变化；
- 作品集叙事是否仍能承接。

避免再次出现“局部流程已经修改，后续页面仍沿用旧逻辑”的断层。
