# 04 任务状态与事件契约

## 1. 管理终端主状态

小程序只读同步以下主状态：

```ts
type WarningStatus =
  | "pending_review"
  | "observing"
  | "formal_warning"
  | "in_intervention"
  | "pending_retest"
  | "referral"
  | "closed";
```

小程序不得直接修改该字段。

---

## 2. 小程序任务类型

```ts
type CollaborationTaskType =
  | "default_observation"
  | "additional_feedback"
  | "feedback_revision"
  | "retest_reminder"
  | "grade_supervision";
```

### 类型含义

- `default_observation`：确认正式预警后系统自动生成；
- `additional_feedback`：心理老师额外请求事实观察；
- `feedback_revision`：原反馈被退回后补充；
- `retest_reminder`：管理终端安排复测后生成；
- `grade_supervision`：超时或明确指派后生成。

---

## 3. 可写任务状态

```ts
type TaskStatus =
  | "pending"
  | "submitted"
  | "returned"
  | "completed"
  | "cancelled";
```

### 派生展示状态

```ts
const isOverdue =
  status === "pending" || status === "returned"
    ? now > dueAt
    : false;
```

禁止把 `overdue` 存成与 `status` 平行且可能冲突的真值。

### 状态转换

| 当前 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| pending | submit_feedback | submitted | 新增反馈记录 |
| submitted | accept_feedback | completed | 心理老师在管理终端确认已满足任务 |
| submitted | return_feedback | returned | 保留原记录并生成补充要求 |
| returned | submit_revision | submitted | 新增补充记录 |
| pending/returned | cancel_task | cancelled | 只读保留 |
| submitted | warning_closed | completed | 已提交记录归档 |
| pending/returned | warning_closed | cancelled | 无需继续处理 |

---

## 4. 反馈记录

```ts
interface ObservationRecord {
  id: string;
  taskId: string;
  authorId: string;
  authorRole: "head_teacher";
  observedAt: string;
  scene: string;
  facts: string;
  frequency?: string;
  duration?: string;
  immediateSafetyConcern: boolean;
  submittedAt: string;
  revisionOfRecordId?: string;
}
```

每次提交新增一条，不更新旧记录正文。

---

## 5. 督办记录

```ts
interface SupervisionRecord {
  id: string;
  taskId: string;
  supervisorId: string;
  method: "message" | "phone" | "in_person" | "resource_coordination";
  summary: string;
  createdAt: string;
}
```

督办记录不代表班主任任务完成。

---

## 6. 推荐事件契约

### 管理终端 → 小程序

| 事件 | 结果 |
|---|---|
| `warning.formalized` | 生成默认观察任务 |
| `feedback.requested` | 生成额外反馈任务 |
| `feedback.returned` | 原任务进入 returned |
| `retest.scheduled` | 生成复测提醒 |
| `task.cancelled` | 任务进入 cancelled |
| `warning.closed` | 活动任务完成或取消 |
| `assignee.changed` | 更新责任人并留痕 |

### 小程序 → 管理终端

| 事件 | 结果 |
|---|---|
| `teacher.abnormal_reported` | 新增待复核线索 |
| `task.read` | 记录已读时间 |
| `feedback.submitted` | 新增反馈记录 |
| `feedback.revision_submitted` | 新增补充记录 |
| `retest.reminder_confirmed` | 记录班主任已提醒 |
| `supervision.recorded` | 新增督办记录 |

## 7. 本开发包采用的 MVP 默认决策

为避免 Agent 自行编业务，本轮先采用以下具体决定：

1. 默认正式预警协作任务只发给对应班主任；
2. “请求补充反馈”MVP 只选择对应班主任；
3. 年级主任只在超时或明确指派时进入；
4. “系统生成默认协作任务”作为独立系统事件留痕；
5. 发起转介不会自动给班主任生成新任务；
6. 安排复测才会生成班主任提醒；
7. 闭环只向仍有活动任务的协作人发送最小结束通知；
8. 班主任不显示管理终端专业风险等级，使用任务紧急程度代替；
9. 驳回、观察中阶段不会生成正式预警后的协作任务；
10. AI 倾诉直接入池与否不影响小程序：未确认正式预警前不生成协作任务。

这些默认决策若与管理终端最终规格发生变化，必须同步更新本文件、页面 PRD、Mock 和验收矩阵。
