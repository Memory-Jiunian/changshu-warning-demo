# 00 项目基线与范围

## 1. 产品定位

畅树学校心理健康系统由三个端协作：

| 终端 | 核心职责 | 不承担 |
|---|---|---|
| 学生端 | 普筛、深度测评、AI 倾诉，产生测评结果和风险线索 | 不展示老师处置流程，不进行专业定级 |
| 小程序端 | 一线异常上报、移动任务触达、事实观察反馈、复测提醒、督办留痕 | 不确认预警、不修改风险等级或主处置状态 |
| 管理终端 | 线索汇集、专业复核、正式预警、干预、复测判断、转介、闭环归档 | 不替代小程序的移动协作 |

小程序不是后台缩小版，而是业务链条中被不同角色、在移动场景下使用的协作工具。

---

## 2. 小程序的两个业务入口

### 2.1 上游辅助入口：班主任主动上报异常

```text
班主任发现异常事实
→ 小程序提交异常上报
→ 管理终端进入待复核线索池
→ 心理老师决定是否补充评估和形成正式预警
```

这个入口用于补充学校日常观察，不等于班主任判断学生存在心理疾病或确定风险等级。

### 2.2 主叙事入口：正式预警后的移动协作

```text
心理老师确认正式预警
→ 系统生成班主任协作任务
→ 班主任查看有限信息与注意事项
→ 班主任提交事实观察
→ 管理终端接收反馈
→ 心理老师继续干预、复测、转介或闭环
```

作品集叙事应以第二条为主，第一条作为一线事实来源补充，避免小程序价值再次被讲成“上传工具”。

---

## 3. 目标用户

### 核心用户

- 班主任；
- 年级主任。

### 次级角色

- 心理老师：管理终端为主，小程序只可保留有限的协作进度查看或 Demo 角色说明，不作为专业处置入口。

### 不进入本轮个案流程

- 校长：在管理终端查看脱敏聚合总览，不在小程序查看学生个案。

---

## 4. 核心用户问题

### 班主任

- 我现在有什么必须处理的协作任务？
- 为什么需要我处理？
- 截止时间是什么？
- 我应该提交哪些事实，而不是做什么心理判断？
- 复测前我需要提醒谁、何时完成？
- 我提交后是否成功，心理老师是否已经收到？

### 年级主任

- 哪些协作任务已经超时或需要协调？
- 我可以看到什么，不能看到什么？
- 我如何留下督办或资源协调记录？
- 如何避免自己越权介入专业判断？

---

## 5. MVP 成功标准

1. 班主任打开首页即可看到待办、超时和今日提醒；
2. 正式预警后可以完成“接收任务—查看要求—提交事实反馈”；
3. 反馈历史不会被覆盖；
4. 复测提醒不会被误解成心理老师的待办；
5. 年级主任只能查看被指派或超时督办事项；
6. 页面不会泄露完整测评、AI 倾诉和心理档案；
7. 小程序提交的数据能够在管理终端找到对应记录；
8. 关键页面在移动端具有清晰层级、稳定底部操作区和完整异常态；
9. Demo 可通过角色切换完整演示至少三条链路；
10. 所有交互均使用统一 mock 真值，刷新或返回后的状态一致。

---

## 6. 非目标

本轮不是生产级医疗系统，不承诺：

- 自动识别真实紧急风险；
- 替代学校既有应急流程；
- 自动诊断；
- 自动向家长、医院或公安发送通知；
- 真实数据安全合规实现；
- 真实消息送达率；
- 真实跨校组织权限。
